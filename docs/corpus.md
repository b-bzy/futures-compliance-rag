# 语料

本页是语料的完整说明：规模、来源、覆盖边界与口径澄清。
所有数字来自 `data/processed/stats.json`，由 [`scripts/02_parse.py`](../scripts/02_parse.py)
自动生成，**是实测值不是估算值**，可在本地重跑复现。

---

## 一、规模

| 指标 | 数值 |
|---|---|
| 抓取文档 | **191 份**（成功 191，失败 0） |
| 交易所 / 监管机构 | **10 家** |
| 解析出正文 | 190 份 |
| 条款级父块 | **5,365 个** |
| 检索子块（进向量库） | **14,710 个** |
| 总字数 | **331 万字** |
| 真正需要 OCR 的页面 | **6 页**（其余全是原生数字排版） |
| 识别出的已废止条款 | 13 个块（检索默认过滤） |

父块按类型拆分：

| 类型 | 数量 | 说明 |
|---|---|---|
| 条文 | 4,365 | "第十二条 ……" |
| 条款表行 | 694 | 合约条款表的一行，如"合约单位 → 10000 份" |
| 问答 | 72 | 交易所 FAQ 的一组问答 |
| 其他（兜底切分） | 234 | 无法识别条文结构的段落 |

**为什么父块和子块要分开**：检索要小块（精度），生成要大块（上下文完整）。
设计理由见 [architecture.md · 为什么是父子索引](architecture.md#为什么是父子索引)。

## 三、抓取与解析

| 环节 | 做法 | 代码 |
|---|---|---|
| 下载 | 1 req/s 限速；内容校验（Content-Type + magic bytes + WAF 指纹） | [`crawl/fetcher.py`](../src/derivrag/crawl/fetcher.py) |
| 列表页枚举 | 各站点独立适配器，支持 manifest 兜底 | [`crawl/adapters.py`](../src/derivrag/crawl/adapters.py) |
| PDF | PyMuPDF 版面 + 表格抽取，逐页双条件 OCR 兜底 | [`parse/pdf.py`](../src/derivrag/parse/pdf.py) |
| HTML | 站点正文选择器 + 页头页脚裁剪 + 问答抽取 | [`parse/html.py`](../src/derivrag/parse/html.py) |
| Word | .doc / .docx，含 Word 自动编号还原 | [`parse/docfile.py`](../src/derivrag/parse/docfile.py) |

两点值得单独说：

- **HTTP 200 不等于抓到了内容**。不校验的话，WAF 验证码页和 `text/html` 冒充的
  PDF 都会以 200 混进语料。加了内容校验后实测 191 份全部通过、0 个验证码页混入
  （见 [decisions.md · D13](decisions.md#d13-http-200-不是有效的健康检查)）。
- **上交所 16 份规则正文只存在于 `.doc` 附件里**，而 Word 的自动编号（"第X条"）
  不在文本流中、只在样式里，直接读会丢掉全部条号 —— 条款级切分就无从谈起。
  还原逻辑见 [decisions.md · D10](decisions.md#d10-word-自动编号还原)。

## 四、关于「10 万条条款」这个口径

简历上常见的写法是"10 万条期权交易条款"。这里如实说明：

**全网可合法获取的境内外期权条款，实测上限约 400 份文档 / 4000 页。**
要凑到 10 万量级，必须同时满足三个条件：

1. 按**子块**计数而非条款计数；
2. 中英双语都算；
3. 把同一部规则的**历次修订各算一份**。

本项目写的是实测数字：191 份文档、5,365 条款级父块、14,710 个子块。

## 五、覆盖边界

### 5.1 深交所只抓到 4 份

深交所所有列表页对普通 HTTP 请求返回 **0 个链接**（客户端渲染），无 sitemap，
JSON API 遍寻不获。所以只抓到了已知直链的 4 份 PDF。

漏掉的高价值语料是**深交所期权入市手册 41 期**（recon 阶段估算约 200 对人工问答），
拿到它可以把 Tier-1 人工金标从 72 扩到 250+，直接缓解当前评测集统计功效不足的问题
（n=150 时小于约 6 pp 的差距不能当作真实差异，见
[RESULTS.md 第 1 节「关于这些数字的稳定性」](../eval/reports/RESULTS.md)）。

正确做法是用 Playwright 一次性采集后固化成 manifest —— 代码里已预留入口，
`adapters.szse_rule` 会优先读 manifest。执行计划见
[audit.md · 2.1](audit.md#21-深交所只抓到-4-份)。

### 5.2 时效性字段覆盖率低

多数交易所文档不写生效 / 废止信息，目前能确定"现行有效"的块占比很低。

检索默认**只过滤明确标记为已废止的**，保留"未知" —— 把未知当废止会丢掉绝大部分
语料。这个取舍写在 [`retrieve/hybrid.py::_where`](../src/derivrag/retrieve/hybrid.py) 里。
每个块携带的完整元数据 schema 见
[architecture.md · 元数据与时效性](architecture.md#元数据与时效性)。

## 六、获取方式与版权

**本仓库不包含任何一份语料。** `data/` 已整体加入 `.gitignore`，
请自行运行抓取脚本获取：

```bash
python scripts/01_crawl.py --include-en     # 约 6 分钟
python scripts/02_parse.py                  # 约 15 分钟，产出 stats.json
```

⚠️ 抓取脚本获取的交易所文档**版权归各自发布机构所有**，不适用本仓库的 MIT 许可。
详细范围说明与合规要点见 [NOTICE.md](../NOTICE.md)。
