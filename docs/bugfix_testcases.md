# 缺陷测试用例集

每个缺陷对应的测试用例，以及**为什么这样设计**。配套的根因分析与方案见
[bugfix_log.md](bugfix_log.md)。

这份文档的价值不在「有哪些用例」，而在**用例的设计意图** —— 哪几条是防止 bug
以同样方式回来的，哪几条是防止「修过头」的，哪几条是把容易被误当成 bug 的正确
行为钉住的。照抄用例没用，照抄这个思路才有用。

## 三类测试的分工

| | 位置 | 测什么 | 判定 | 成本 |
|---|---|---|---|---|
| 单元测试 | `tests/` | 函数契约，含分支与边界 | `pytest` 自动 | 零（全 stub） |
| 健壮性探针 | [`eval/robustness_probe.py`](../eval/robustness_probe.py) | 系统会不会崩、会不会静默出错 | 自动断言，退出码非 0 即有缺陷 | A–F 组零成本，G 组约 0.1 元 |
| 人工清单 | [`eval/manual_test_questions.md`](../eval/manual_test_questions.md) | 答案质量：命中、正确、引用、无幻觉 | 人工 4 维打勾 | 每题一次问答 |

**关键认识**：本文记录的两个缺陷，人工清单**一条都发现不了**。空答案不是「答错」
而是「没答」；HyDE 静默失效根本不改变答案、只是白花钱。这两类都不在「检索命中 /
答案正确 / 引用准确 / 无幻觉」四个维度里。所以三类测试不能互相替代。

## 设计原则

1. **不联网、不花钱、不加载模型。** 全部用 stub。否则没人会在每次改动后跑它。
2. **每条用例对应一个真实踩过的坑**，而不是为覆盖率凑数。
3. **负例和正例一样重要。** 「返回 `None` 是正确行为」这种最容易被后来的人当成
   bug 然后「修」出一堆假阳性。
4. **把「bug 会怎么回来」写成用例。** 重复常量、默认值漂移、配置与代码不一致。

## 缺陷 1 的用例

推理模型思考吃满预算导致正文为空。文件：
`tests/test_provider_truncation.py`（15 例）、`tests/test_hyde_degradation.py`（9 例）。

### 截断处理（6 例）

| 用例 | 设计意图 |
|---|---|
| 正常返回不重试、不改预算 | 防止修过头：给正常路径加重试会白白翻倍成本 |
| 空 + `length` → 提 3 倍重试并成功 | 主路径 |
| 重试预算封顶 16384 | 防止成本失控。若不封顶，`max_tokens=8192` 的重试会是 24576 |
| 重试后仍空 → 抛错，且**只重试一次** | 断言 `calls == 2`。不断言次数的话，将来改成循环重试也能过，成本失控无人察觉 |
| 空 + `stop` → **不重试**直接抛错 | `finish_reason` 不是 `length` 说明不是预算问题，重试纯属浪费一次调用 |
| 未闭合 `<think>` 等同空 | 部分后端把思考直接写进 `content`，`_strip_thinking` 会返回空串，必须走同一条路径 |

### 输出预算下限（6 例）

| 用例 | 设计意图 |
|---|---|
| 256 被抬到 1024 | 主路径 |
| 4096 不被干预 | 防止修过头：下限不该改变本来合理的预算 |
| **下限可关闭**（设 0） | 非推理模型不该被强行抬高。没有这条，将来换模型时没人知道能关 |
| **只告警一次** | 去泄漏改写连着调 222 次。刷屏等于没有告警 —— 这条断言的是「可用性」而非「正确性」 |
| 流式路径同样受保护 | 两条代码路径，容易只改一条 |
| provider 自身 `max_tokens` 过小也兜住 | 下限不能只拦调用方传参 |

### HyDE 降级（9 例）

| 用例 | 设计意图 |
|---|---|
| 截断记 **ERROR** 且含「已付费但无收益」 | 断言**日志级别**，不只是断言不崩。级别错了，问题会淹没在日志里 |
| 返回空串（而非抛错）也记 ERROR | provider 可能返回空串而不抛异常，两条路都要堵 |
| 网络异常仍记 **WARNING** | 防止修过头：把运行时波动升成 ERROR 会让告警失去区分度，最终所有 ERROR 都被忽略 |
| 部分成功保留已付费的那几份 | `n=3` 时第二份为空，不该整批丢弃 |
| **默认预算不是 256** | 防 bug 回来：该常量曾同时存在于三处 |
| **改写默认预算不是 200** | 同上，另一处 |
| 改写失败原样返回问题 | 不能返回空串把查询清空 —— 那会让检索退化成空查询 |
| `pipeline` 兜底默认值 ≥ 1024（**读源码正则断言**） | 第三处重复常量。这条直接 `re.search` 源文件，是唯一能钉住「三处一致」的办法 |
| `config.yaml` 的值本身也够用（**读 yaml 断言**） | 代码默认值对了但配置文件写小了，照样出问题 |

> 最后两条是这组里最不常见的写法：**测试直接读源码和配置文件**。一般不推荐，
> 但重复常量这个问题只有这样才能钉住 —— 任何一处被改小，测试立刻红。

## 缺陷 2 的用例

关键词通路无法定位到具体文档。文件：`tests/test_keyword_channel.py`（13 例）。

### Stub 设计

构造 4 个块的假语料，**三份不同文档都有「第十二条」** —— 这是真实语料的关键
特征（库里 59 个同名条号）。不这么造，文档维度约束的价值就测不出来。

`_FakeVS.query_metadata` 实现了 `clause_id` / `doc_no` / `$and` / `$in` 的匹配语义，
因为修复依赖 Chroma 的这几个操作符（已实测确认支持）。

### 文档维度约束（8 例）

| 用例 | 设计意图 |
|---|---|
| 《规则名》解析出 `doc_id` | 主路径 |
| **子串双向包含** | 库里是「关于发布《X》的通知（附件）」，用户只写《X》，相等匹配永远失败。这条钉住「不能用 `==`」 |
| `《说明》` 这类短词被忽略 | 防止修过头：短词会匹配到大量无关文档，反而扩大噪声 |
| 标题匹配不到时退回无约束 | 用户可能写了个语料里没有的文件名，不能因此返回空 |
| **带规则名只返回目标文档那一条** | 核心断言：`len(out) == 1`。不断言数量的话，返回 3 份同名条款也能过 |
| 不带规则名返回全部同名条号且**不标精确** | 钉住原有行为不被破坏，同时确认「不知道是哪份」时不冒充精确 |
| 点名文件里没那一条时退回全库、**不标精确** | 退回结果是猜测，不能享受置顶特权 |
| **文号单独也算点名文档** | 文号是文档唯一标识，不需要书名号 |

### 精确匹配置顶（5 例）

| 用例 | 设计意图 |
|---|---|
| 融合丢掉它时置顶，且总数不超 `want` | 主路径。**这条是缺陷 2 真正的用户可见修复** —— 没有它，通路修好了用户也看不到变化 |
| 已在结果里就不改动顺序 | 防止修过头：不该为了置顶而打乱本来正确的排序 |
| **置顶数量封顶** | 一个文号最多覆盖 117 个块，全置顶会挤爆 `top_k`、挤掉其他相关条款 |
| 无精确匹配时是 no-op（断言 `is` 同一对象） | 绝大多数查询不触发这条路径，不该有任何开销或副作用 |
| 置顶项在 `component_ranks` 里标 `exact` | 界面要能显示「这条是精确匹配置顶的」而非某路召回的，否则检索过程剖析页会说谎 |

## 健壮性探针里的对应用例

[`eval/robustness_probe.py`](../eval/robustness_probe.py) 里有两条是这两个缺陷的
**端到端回归**，跑的是真实服务：

| 用例 | 对应缺陷 | 说明 |
|---|---|---|
| `G2` 曾返回空答案的问题 | 1 | 用那个稳定复现的真实问题「备兑开仓的保证金怎么算？」。单元测试用 stub 证明逻辑对，这条证明真实模型上也对 |
| `C2` 带明确条号时 keyword 通路应参与 | 2 | 断言 `channel_counts` 含 `keyword`。这是从**系统外部**能观测到的症状 |
| `C3` 带明确文号时 keyword 通路应参与 | 2 | 文号路径与条号路径是两套代码 |

修复前 `34/37`，修复后 **`37/37`**。

> 探针自身也出过一个假阳性：`A10` 模板注入用例原先断言「响应里不出现 49」，
> 被延迟浮点数 `0.6981286249938421` 误伤。改为断言 `query` 原样回显未被求值。
> **教训：断言要针对语义，不要针对字符串的偶然出现。**

## 怎么跑

```bash
# 单元测试（零成本，每次改动都该跑）
PYTHONPATH=src .venv/bin/python -m pytest tests/ -q

# 健壮性探针（需先起后端）；--no-llm 跳过唯一花钱的 G 组
PYTHONPATH=src .venv/bin/uvicorn derivrag.api.server:app --port 8000 &
PYTHONPATH=src .venv/bin/python eval/robustness_probe.py --no-llm
PYTHONPATH=src .venv/bin/python eval/robustness_probe.py --group C   # 只跑某组

# 静态检查
.venv/bin/python -m ruff check --select F,E9 src/ scripts/ tests/ eval/
```
